# 扩展简报（HEAVY 任务用）

> 四行简报对 LIGHT 够用；HEAVY（跨模块/长任务/复杂重构）用本模板。
> 来源：orchestration-kit `01-task-card.md`（六节任务卡）精简而来，按重任务的实际需要保留增量信息。

```markdown
## 任务卡 T-<YYYYMMDD>-<序号>（HEAVY）

### 1. 目标（必须可验收）
完成态长什么样，一句话说清。禁止"改一下""优化下"。

### 2. 背景与文件地图（最小上下文）
- 仓库 / 分支:
- 涉及文件（**逐个列出**，含"只读参考"和"可修改"区分）:
  - `src/api.py` — 可改
  - `docs/spec.md` — 只读参考
- 关键符号 / API 契约（签名、数据结构，5~20 行代码）:

### 3. 约束（红线）
- 不得修改的文件:
- 依赖约束（允许/禁止引入）:
- 风格 / 兼容性要求（从 USER.md 注入偏好）:
- **增量 commit 纪律：每完成一个可独立验证的子模块 commit 一次，不要攒到最后**

### 4. 验收标准（客观、可勾选、含命令）
- [ ] 命令 `____` 通过（测试 / lint / build）
- [ ] 新增测试覆盖关键路径
- [ ] 无新增 TODO / FIXME / 注释掉的死代码
- [ ] API 兼容 / 调用方无需改动

### 5. 返回要求
按简报格式返回：改了哪些文件 + 测试结果（真实输出）+ 遗留问题。--commits 传下限（最少产出 commit 数）。

### 6. 上下文预算
- 预期改动: ≤ ____ 行 / ____ 个文件
- 超出预算即停，回传 partial 并说明，禁止自行扩大范围。
```

## 使用规则

1. 判定 HEAVY 后**直接用本模板**，不要硬塞四行简报。
2. "背景"只给最小上下文（文件地图 + 关键符号），别把整个仓库塞进去。
3. 验收标准必须含可执行命令。
4. 增量 commit 纪律是默认条款，写进任务串。
